# 0. この追補の目的

#015では最終投稿まで完了した一方、制作途中で以下の重要な躓きが発生した。

1. テーマ重複チェックが甘く、当初「世界5分前仮説」を#015として選んだが、実際には#013で既制作だった。
2. 次候補「経験機械」は作品名の重複ではないものの、#003「水槽の中の脳」Page 8の中心問いと意味的に近かった。
3. 背景生成で、1枚背景ではなく文字入りストーリーボード／8分割コラージュが繰り返し生成された。
4. 不適切な複合画像を途中で切り出して使うという例外処理を行った。これは再現性と品質の観点から今後は禁止する。
5. Canva上に実データが存在する前に「プレビュー状態」「保存可能」と誤って報告した場面があった。
6. Canvaコピー操作を複数回実行し、不要なWorking Copyを複数作った。
7. 編集トランザクションが失効し、保存承認後に同一内容を再適用してcommitするRecoveryが必要になった。

今後は、各工程を **「すべきこと」と「すべきでないこと」** に明確に分離する。

---

# 1. テーマ選定

## すべきこと

- 作品番号を決める前に、GitHub `content/experiments/`、`content/publishing/`、Canva作品フォルダ／完成デザインを確認する。
- 「作品名の重複」だけでなく「中心問いの重複」も確認する。
- 過去作品のPage 1 Hook、A/B選択、Page 8第二の問いまで見て、意味的な重複を判定する。
- 同じカテゴリが連続している場合は、人間・道徳・幸福・社会・科学・未来など別カテゴリへの分散を検討する。
- テーマ選定後にFact Packを作り、原典または信頼できる出典で設定を確認する。
- 「未使用である」「中心問いも既投稿と十分に異なる」の2条件を満たしてから制作へ進む。

## すべきでないこと

- 本の掲載順や古い候補リストだけで作品番号を決めない。
- 「タイトルが違うから別テーマ」と判断しない。
- 記憶だけで既制作テーマを判定しない。
- 作品番号とテーマの対応が未確認のままGitHub・Canvaへ新規ファイルやフォルダを作らない。
- 重複が判明した旧案をCanonicalとして残さない。

### テーマ重複チェックの最低条件

```text
[ ] GitHub既存Fact Pack確認
[ ] GitHub既存Production Pack確認
[ ] Canva完成デザイン／作品フォルダ確認
[ ] 過去作品の中心問い確認
[ ] A/B選択の意味重複確認
[ ] Page 8第二の問いの意味重複確認
[ ] 未使用テーマである
[ ] 既投稿と論点が十分に異なる
```

# 2. 背景画像生成

## すべきこと

- 1ページにつき1枚、独立した9:16背景画像として生成する。
- 1回の生成依頼では原則1ページ分だけを扱う。
- プロンプトは視覚情報だけに絞る。
- `NO TEXT / NO LETTERS / NO NUMBERS / NO LOGO / NO UI / NO PANELS / NO COLLAGE` を明示する。
- 各ページごとに、そのページの意味と一致する重要オブジェクト、距離、光、Text Zoneを定義する。
- 生成後、Canva投入前に1枚ずつSemantic QCを通す。
- 1枚でも不合格なら、そのページだけ再生成する。

## すべきでないこと

- 8ページ分の台本や役割を1つの画像生成プロンプトへまとめない。
- 「ストーリーボード」「インフォグラフィック」「8 panels」「2×4 grid」など、複数パネルを連想させる語を入れない。
- 文字入り・複数分割・コラージュ画像を“素材として使える”と判断しない。
- コラージュから8枚を切り出してCanonical背景として採用しない。
- 生成失敗画像を部分修正し続けて救済しない。
- 背景生成段階で投稿コピー、A/B、ページ番号、ブランド名を焼き込まない。

### 生成失敗時の標準処理

```text
文字入り / 複数分割 / コラージュ / 企画書化
        ↓
即不採用
        ↓
プロンプトを短くする
        ↓
1ページ・1画像だけで再生成
        ↓
Semantic QC
```

**例外として切り出しで救済する運用は禁止する。**

# 3. Canvaへの素材投入

## すべきこと

- 8枚の背景がQC合格してからCanvaへアップロードする。
- 作品専用フォルダを1つだけ作る。
- 背景asset名を `作品番号_ページ番号_役割_background` 形式で統一する。
- 8背景を専用フォルダへ移動したことを確認する。
- コピー元は検証済みLayeredデザイン1件に固定する。
- Canonical Working Designは1件だけ作る。
- Working Design IDをProduction Packへ記録する。

## すべきでないこと

- 背景が揃う前に複数のWorking Copyを作らない。
- `copy-design` を結果確認せず連続実行しない。
- 同一作品のWorking Copyを複数Canonical候補として残さない。
- コピー元の旧作品名・旧背景・旧本文が残った状態を完成候補と呼ばない。

### Copy Guard

```text
copy-design 実行
↓
返却された Design ID を記録
↓
get-design で1件確認
↓
そのDesign IDだけをCanonical Working Designとして使う
```

**同じ目的で2回目のcopy-designを呼ぶ前に、1回目の結果を必ず確認する。**

# 4. Canva編集

## すべきこと

- 既存全ページ背景の差し替えは `update_fill` を使う。
- 文字はCanva上の編集可能テキストとして置換する。
- 8ページのコピーを先に確定してから一括編集する。
- ページ固有の文章量に応じて、position / width / font sizeをサムネイルで確認する。
- A/Bは十分な縦間隔を確保する。
- Page 1、選択ページ、Page 8はTikTok Safe Areaを重点確認する。
- 編集操作後、8ページすべてのthumbnailを確認する。

## すべきでないこと

- `insert_fill` で旧背景の上に新背景を重ねない。
- 背景画像の中に投稿文字を焼き込まない。
- 旧テンプレートの位置をそのまま信用しない。
- 1ページだけ確認して「全8ページ完成」と判断しない。
- Canvaの編集結果が返る前に「反映済み」と報告しない。

# 5. 状態報告ルール

#015で最も重要な反省点の1つ。**UI上で実際に確認できた状態だけを報告する。**

## すべきこと

状態を以下の4段階に分ける。

### A. ASSETS READY

```text
8背景assetが存在し、QC済み
```

### B. DRAFT VALID

```text
Canva editing transaction内で編集済み
+ 8ページthumbnail確認済み
```

### C. COMMITTED

```text
commit-editing-transaction が committed
```

### D. FINAL VERIFIED

```text
commit後read-back成功
+ final folder audit成功
```

ユーザーへの表現も状態に合わせる。

```text
A: 背景素材が揃いました
B: 保存前プレビューができました
C: Canvaへ正式保存しました
D: 保存後監査まで完了しました
```

## すべきでないこと

- 実際にCanvaデザインが存在しないのに「Canvaで完成」と言わない。
- editing transactionを開始していないのに「保存前プレビュー」と言わない。
- commit前に「保存済み」と言わない。
- folder audit前に「9アイテム構成を確認済み」と言わない。
- 推測や予定を完了形で報告しない。

### Evidence First Rule

> 「したつもり」ではなく、tool response / read-back / folder list で確認した事実だけを完了として報告する。

# 6. 保存承認とトランザクション

## すべきこと

- 8ページのプレビューをユーザーへ提示する。
- 明示的な「保存」承認を受ける。
- 承認後は同じtransaction_idを最優先で即commitする。
- commitが失敗・失効した場合は、Canonical Design ID / Asset IDs / Final Copyを使って復元する。
- 復元内容が承認済み内容と同一であることを確認してからcommitする。
- commit成功後、get-design / get-design-contentでread-backする。

## すべきでないこと

- 保存承認後に不要な別作業を挟まない。
- transaction失効時に内容を変更しない。
- Recoveryを「新しい案」として再解釈しない。
- commit成功前に「保存完了」と言わない。

---

# 7. Final Folder Audit

## すべきこと

完成時は専用フォルダを必ずlistし、次を確認する。

```text
[ ] canonical background 8枚
[ ] final design 1件
[ ] 合計9件
[ ] design titleが作品番号・作品名と一致
[ ] 旧テーマassetがない
[ ] 不要Working Copyがない
```

## すべきでないこと

- 9件という件数だけで合格にしない。
- 不要コピーや旧案が別場所に大量に残っているのを無視しない。
- final designが専用フォルダ外にある状態で完成としない。

# 8. 今回の#015固有の反省

## 良かったこと

- 「世界5分前仮説」の重複に気づいた後、採用を止めた。
- 「経験機械」も#003との中心問いの近さを見て見送った。
- 最終的に「ヤマアラシのジレンマ」へ変更し、既投稿と異なる対人関係テーマに分散できた。
- 保存前プレビュー、commit、read-back、9件folder auditまで最終的には実行できた。

## 改善すべきこと

- 重複チェックは制作前に完了させるべきだった。
- 背景生成の失敗を何度も繰り返す前に、v1.8の「視覚情報だけ」ルールへ戻すべきだった。
- 8分割画像の切り出しは、品質基準を下げる例外処理だったため今後は禁止する。
- Canvaコピーを複数回作成したのは操作ミス。Canonical Working Designは常に1件だけにする。
- 実データ未確認の段階で「プレビュー済み」「保存可能」と報告してはいけない。

# 10. 最終チェック｜DO / DON'T

## DO — 必ずする

- 既作品の実データを確認してからテーマを決める
- 中心問いまで重複チェックする
- 背景は1ページ1枚、1回1枚で生成する
- 不合格背景は再生成する
- CanvaのCanonical Working Designは1件だけにする
- 8ページ全てをプレビューする
- 保存承認後は即commitする
- commit後read-backする
- final folderを9件構成まで監査する
- ツールで確認した事実だけを完了報告する

## DON'T — 絶対にしない

- 候補リストだけで作品番号を決める
- タイトルだけで重複判定する
- 8枚を1枚のコラージュとして生成する
- コラージュを切り出してCanonical背景にする
- 文字入り生成画像を背景として採用する
- copy-designを結果確認なしで連打する
- Canva実データ未確認で「完成」「保存前」と報告する
- commit前に「保存済み」と報告する
- folder audit前に「完成」と報告する
- 失敗を隠すために状態を推測で補完する

# 11. 完成定義 v1.9

以下をすべて満たした時だけ、作品を「完成」と呼ぶ。

```text
テーマ重複チェック済み
+ Fact Pack確定
+ 8ページFinal Copy確定
+ 背景8枚が個別生成・QC済み
+ Canva editable text化済み
+ 8ページpreview済み
+ user approval済み
+ commit成功
+ read-back成功
+ final folder audit成功
+ 投稿素材（title/caption/pinned comment）確定
```

投稿完了後は、同じ会話内で発生した躓きを次版追補へ反映する。
