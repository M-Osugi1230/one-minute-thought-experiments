# 1分思考実験｜TikTok写真カルーセル投稿 作成マニュアル

Version: 1.1  
Established: 2026-08-24  
Validated posts: #001 トロッコ問題 / #002 テセウスの船

---

## 0. このマニュアルの目的

この文書は、「1分思考実験」のTikTok写真カルーセル投稿を、毎回ゼロから考え直さず、一定品質で再現するための標準作業手順（SOP）である。

現在の基本フォーマットは、**9:16の写真カルーセル（スワイプ式）**。顔出し・本人ナレーションに依存せず、視聴者自身を思考実験の主人公にして、画像・短い文章・選択・コメントによって参加させる。

最重要原則は次の6つ。

1. **哲学を説明する前に、視聴者に選ばせる。**
2. 思考実験名から始めず、**「あなたならどうする？」の状況から入る。**
3. 1投稿の中で、**状況 → 選択 → 条件変更 → 再選択**をつくる。
4. 結論を教えて終わらず、**コメント欄を第二部にする。**
5. 背景画像は意味を持たせ、Canvaでは原則として**背景1枚＋編集可能な文字だけ**にする。
6. **制作開始時に必ずこのマニュアルを基準にし、自己流の代替工程を勝手に挟まない。**

---

# 1. 投稿1本の完成条件（Definition of Done）

1本の投稿は、次の状態になった時点で「完成」とする。

- 思考実験のFact Packがある
- 基本状況と論点が事実確認済み
- 基本形と後世の変形・追加条件が区別されている
- Hookが視聴者起点になっている
- 7〜9枚程度のカルーセル構成が完成している（標準は8枚）
- 各ページの役割が1つに絞られている
- 各ページの文章が確定している
- **意図した改行位置まで文章仕様として確定している**
- ページごとの背景画像が生成・確定している
- 背景画像のファイル名とページ対応が記録されている
- Canva上で背景と文字が正しいレイヤー順になっている
- 文字が全ページで実際に表示されている
- **不自然な自動折り返しが残っていない**
- 背景の重要オブジェクトを文字が隠していない
- TikTokのUI安全域を侵していない
- A/Bなどの選択肢が中立に表示されている
- 最後に第二の問いまたはコメント誘導がある
- **8ページすべての実サムネイルを確認済み**
- キャプション、ハッシュタグ、固定コメントが完成している
- 投稿後にKPIを記録できる投稿パックが作られている

# 2. 標準ワークフロー

```text
テーマ選定
  ↓
Fact Pack作成・事実確認
  ↓
Hook設計
  ↓
8ページ構成
  ↓
各ページの文章確定
  ↓
改行・強調語まで確定
  ↓
背景画像の設計
  ↓
各ページを1枚ずつ画像生成
  ↓
画像名・ページ対応の固定
  ↓
Canva組み込み方式を決定
  ↓
背景fill差し替え
  ↓
文字差し替え
  ↓
8ページ最終QC
  ↓
改行QC
  ↓
Canva保存
  ↓
投稿パック作成
  ↓
TikTok投稿
  ↓
1h / 24h / 72hでPDCA
```

### 絶対に飛ばさない工程

- Fact Pack
- 文章確定
- ページ別背景設計
- 画像とページ対応の固定
- Canvaの実サムネイル確認
- 改行QC

### 禁止する迂回

以下は、ユーザーから明示的に求められない限り行わない。

- 8ページ分を1枚のストーリーボードとして生成する
- 画像生成がうまくいかないために、勝手にPython等で簡易背景へ置き換える
- 既存の完成テンプレートがあるのに、別方式のCanvaデザインを新規生成する
- マニュアルにない工程を「代替策」として独断で本番採用する

# 3. Step 1｜テーマを選ぶ

テーマ選定では、「有名か」だけでなく、短尺で視聴者が自分の問題として選択できるかを優先する。

評価軸：

- 1〜2枚で状況を理解できるか
- A/Bまたは明確な葛藤があるか
- 条件変更を加えられるか
- コメントで理由が割れそうか
- 背景を視覚化しやすいか
- 思考実験名を知らなくても成立するか

初期シリーズでは、参加しやすさを優先する。

例：

- #001 トロッコ問題
- #002 テセウスの船
- #003 水槽の脳

---

# 4. Step 2｜Fact Packを作る

投稿文章を先に書かない。最初に、思考実験の「変えてはいけない事実」をFact Packとして固定する。

標準保存先：

```text
content/experiments/{ID}_{slug}.yaml
```

最低限含める項目：

- title
- one_line_summary
- core_question
- viewer_role
- initial_state
- available_action
- action_result
- inaction_result
- constraints
- choices
- variation_question
- philosophical_focus
- facts
- sources
- must_include
- must_not_include

### 原典と変形の扱い

書籍はテーマ選定・理解の起点として使えるが、**書籍本文やスクリーンショットをそのまま投稿素材にしない。** 投稿用文章は独自に再表現する。

必要に応じて原典や信頼できる資料で、基本形・作者・成立時期を確認する。

思考実験の変形を使う場合は、基本形と混同しない。

例：

- トロッコ問題の「その1人が家族だったら？」は追加の条件変更
- テセウスの船の「古い部品を組み直してもう1隻作る」は後世の追加条件

**短尺化のために説明を削っても、歴史的・概念的な区別まで消さない。**

---

# 5. Step 3｜Hookを決める

Hookは思考実験名ではなく、視聴者の判断から始める。

### 良い形

- 「5人を助けるために、1人を犠牲にできますか？」
- 「全部の部品を交換した船は、まだ同じ船ですか？」
- 「今見ている世界が全部偽物でも、あなたは気づけますか？」

### 避ける形

- 「今日はトロッコ問題を解説します」
- 「哲学者○○が考えた有名な思考実験です」
- 冒頭から答えや思想名を説明する

### Hookの基準

- 1秒で意味が取れる
- 「自分なら？」が発生する
- 続きをスワイプする理由がある
- 固有名詞を知らなくても理解できる

---

# 6. Step 4｜標準8ページ構成

8ページを基本形とする。ただしテーマによって7〜9枚に調整してよい。

| Page | 役割 | 内容 |
|---|---|---|
| 1 | Hook | 一番強い問い。視聴者を止める |
| 2 | Scene | 状況説明。何が起きているか |
| 3 | You / Mechanism / Change | 視聴者の立場・操作・進行変化 |
| 4 | Conflict | 葛藤や矛盾を明示 |
| 5 | Choice | A/Bなど最初の回答を要求 |
| 6 | Condition Change | 家族・記憶・追加条件などを変更 |
| 7 | Reveal / Context | 思考実験名と最低限の背景 |
| 8 | Your Answer | 最初と最後の変化＋コメントCTA |

### 構成原則

- 1ページ1メッセージ
- 説明を一気に詰め込まない
- 選択の前に必要な条件は揃える
- 第三の抜け道を勝手に追加しない
- A/Bのどちらかを正解のように見せない
- 思考実験名は後半に出す
- テーマに応じてPage 3の役割名は変更してよい

---

# 7. Step 5｜文章を確定する

文章は、**画像を見ながら読むカルーセル**として設計する。

### 文章量

- 主見出し：1〜3行
- 補足：1〜2行
- 1ページ内で長文説明しない
- 同じ情報を背景と文章で二重説明しない

### トーン

- 短い
- 直接的
- 「あなた」を使う
- 過剰に煽らない
- 視聴者の人格を評価しない
- 哲学的立場を正解扱いしない

### 強調

重要語だけ暖色ゴールドで強調する。

例：

- 5人
- 1人
- あなた
- 家族
- 全部
- 同じ船
- テセウスの船
- A / B

## 7.1 改行も文章仕様の一部

#002で、文章自体は正しくてもCanvaの自動折り返しにより、意味の途中で不自然に改行される問題が起きた。

そのため、**文章確定時に改行位置も決める。**

### 良い改行

```text
全部の部品を
交換した船は、
まだ同じ船ですか？
```

### 避ける改行

```text
全部の部品を交換した
船は、まだ同じ
船ですか？
```

### 改行ルール

- 助詞の直後だけが孤立しない
- 主語と述語を極端に離さない
- 強調語が1行に収まりやすいようにする
- 1行が極端に短くならない
- 意味のかたまりで切る
- 文字サイズを先に小さくして逃げない

---

# 8. Step 6｜背景画像を設計する

現在の標準ビジュアル：

**Dark Cinematic + Minimal Editorial**

### 基本仕様

- 縦 9:16
- 最終Canvas：1080 × 1920
- 深い黒〜チャコール
- 暖色の金・アンバー光
- 必要に応じて冷たいスチール／青黒
- 映画的な霧、光、粒子
- 写実寄り
- 背景に文字・ロゴ・数字・UIを生成しない
- 過剰な血やショッキング描写は使わない

### 画面設計

文字は主に左側に置くため、画像生成時から**左上〜左中央にnegative space**を確保する。

重要オブジェクトは右・右下・中央下へ寄せる。

### 共通画像生成プロンプトの骨格

```text
9:16 vertical cinematic scene for a philosophical thought experiment.
Dark cinematic + minimal editorial aesthetic.
Deep charcoal and black tones, muted warm amber/gold practical light,
selective cool steel shadows, subtle volumetric fog, fine film grain,
realistic materials, restrained composition.
Leave generous dark negative space in the upper-left / left-center for Japanese typography.
Place the key narrative object in the lower-right or right side.
No text, no letters, no numbers, no signage, no logos, no UI, no watermark.
No gore. Avoid generic stock-photo aesthetics.
```

この後に各ページ固有の状況を追加する。

## 8.1 画像生成は「1ページ＝1画像」

#002では、8ページ分をまとめて生成しようとして、1枚のストーリーボード／インフォグラフィックとして生成される失敗が起きた。

今後は、**1ページにつき1回の独立した画像生成**を基本とする。

### NG

```text
8ページ分の背景を1回で生成
→ 8コマ構成・文字入り・番号入りになる
```

### 正解

```text
Page 1 背景を1枚生成
Page 2 背景を1枚生成
...
Page 8 背景を1枚生成
```

特にPage 1とPage 6は投稿の反応を左右しやすいため、他ページより厳しく見る。

## 8.2 画像生成に失敗した場合

画像生成が期待どおりでない場合も、**品質を下げる代替物へ独断で置き換えない。**

原則：

1. プロンプトをページ単位で修正
2. 再生成
3. それでも難しい場合のみ別方式を検討
4. 別方式が品質基準を下げるなら、本番素材には採用しない

Python等で作る簡易グラフィックは、ユーザーが明示的に求めた場合や、最終品質として妥当な場合を除き、本番背景にしない。

# 9. Step 7｜背景画像の役割をページごとに変える

8枚すべてを同じ強度にしない。

| Page | 背景の役割 |
|---|---|
| 1 | Hero。最も強い |
| 2 | 状況を伝える |
| 3 | 操作・変化・進行を明確に見せる |
| 4 | 葛藤の構造を見せる |
| 5 | 判断に集中できるミニマル背景 |
| 6 | 条件変更を視覚化。A/Bを中立にする |
| 7 | 解説を邪魔しない静かな背景 |
| 8 | 余韻。最も静かでもよい |

背景画像自体に重要オブジェクトが描かれている場合、**Canvaで同じオブジェクトを追加しない。**

原則：

> 完成した背景画像 ＋ 文字

だけで成立させる。

---

# 10. Step 8｜画像名とページ対応を固定する

画像生成後は、Canvaに入れる前にページ対応を確定する。

標準記録形式：

```text
Page 1: {filename}
Page 2: {filename}
...
Page 8: {filename}
```

重要なのは、**ページ番号との対応表を正本として残すこと。**

アップロード後は、ファイル名だけでなくサムネイルも照合する。

Canvaフォルダにユーザーが `1`〜`8` のように画像を格納している場合も、**番号だけを信用せず内容を確認する。**

# 11. Step 9｜Canvaへの組み込み

## 11.1 組み込み方式の優先順位

#002で、既存の8ページテンプレートがあるにもかかわらず別HTMLインポートを試し、不要な1ページデザインが生成された。

今後は次の優先順位にする。

### A. 検証済みの再利用可能テンプレートがある場合

**既存の完成テンプレートを複製・再利用し、背景fillと文字だけを差し替える。**

これを最優先とする。

```text
検証済みテンプレート
  ↓
背景fillをupdate_fill
  ↓
文章を差し替え
  ↓
QC
```

### B. 再利用可能テンプレートがない場合

**HTMLテンプレートをCanvaへインポート → 背景プレースホルダーのfillを生成画像へ差し替える。**

HTMLの基本条件：

- 1080 × 1920
- 8つのトップレベルページ
- 各ページに `data-document-role="page"`
- 必要なら `data-label` を付ける
- 背景用の全画面画像／shapeを最初から1つ入れる
- その上にテキストを置く

## 11.2 最重要：Canvaレイヤー事故を防ぐ

#001制作で実際に起きた失敗：

1. 文字だけのCanvaデザインを作った
2. 後から全画面背景画像を `insert` した
3. 新しい背景画像が文字より前面に積まれた
4. テキスト要素は存在するのに画面では見えなくなった

### NG

```text
文字を先に作成
↓
完成画像を全画面で後からinsert
```

### 正解

```text
背景プレースホルダーを最初から作る
↓
その上に文字を作る
↓
背景プレースホルダーのupdate_fillで画像だけ交換
```

**背景を新規挿入せず、既存背景fillを差し替える。**

## 11.3 テキスト差し替えルール

#002では、既存テキストの装飾regionを維持しようとして断片的な文字列置換を重ね、一時的に文章が壊れた。

今後は次を守る。

- 先に各ページの最終全文を確定する
- 強調語も先に確定する
- 既存文章を場当たり的に何度も部分置換しない
- 非responsiveページで全文差し替えが安全なら `replace_text` を優先
- 装飾維持のため部分置換が必要な場合は、**最終形への置換順序を事前に設計する**
- 置換直後に文章が文法的に成立しているか確認する
- 旧テーマ固有語が残っていないか確認する

### 特に確認する事故

- 「〜がいます」が別テーマに残る
- 強調語だけ旧テーマのまま残る
- 句読点だけ不自然に残る
- 旧テーマの名詞が部分一致で残る

# 12. Step 10｜Canvaデザイン仕様

### Canvas

- 1080 × 1920

### 安全域の目安

- Left: 72〜76px以上
- Top: 150〜200px以降を主領域にする
- Right: TikTok UIを考え、重要文字は右端まで伸ばさない
- Bottom: 320〜380px程度をUI回避域として意識

### 標準文字位置

- ブランド名：上部左
- ページ番号：上部右だが、右端から十分内側
- 英語kicker：上部左
- 主見出し：上〜中央
- 補足：下側だがTikTok UIより上

### 文字サイズの目安

- 主見出し：約80〜90px
- 本文：約48〜54px
- 小見出し：約22〜34px
- A/B：約60px前後

### 配色

- 本文：off-white / white
- 強調：warm gold
- 背景：dark charcoal / black

### 文字サイズと改行の優先順位

不自然な折り返しが起きた場合、まず改行位置を調整する。

```text
1. 意味単位で改行を指定
2. テキストボックス幅を確認
3. それでも収まらない場合に限り文字サイズを微調整
```

**安易にフォントを小さくして解決しない。**

# 13. Step 11｜Canva最終QC

「要素が存在する」だけでは合格にしない。

**実際のサムネイルを8ページすべて見る。**

## 13.1 表示

- [ ] 文字が実際に見えている
- [ ] 背景が文字を覆っていない
- [ ] 画像が欠けていない
- [ ] ページ番号が1/8〜8/8になっている

## 13.2 読みやすさ

- [ ] 主見出しが背景に埋もれていない
- [ ] ゴールド文字のコントラストが十分
- [ ] 文字が重要オブジェクトを隠していない
- [ ] 1ページの文章量が多すぎない
- [ ] **意味の途中で不自然に改行されていない**
- [ ] **短すぎる孤立行がない**
- [ ] **強調語と改行の位置が自然**

## 13.3 文章

- [ ] 文法的に成立している
- [ ] 旧テーマの単語が残っていない
- [ ] 同じ内容を重複していない
- [ ] 助詞・句読点が不自然に残っていない

## 13.4 意味

- [ ] 背景と文章の意味が一致している
- [ ] Page 3の操作・変化が明瞭
- [ ] Page 4の葛藤構造が伝わる
- [ ] Page 5のA/Bが中立
- [ ] Page 6の条件変更が基本形と混同されていない
- [ ] Page 7の歴史的説明が短くても正確

## 13.5 TikTok

- [ ] 右側UIに重要文字が重ならない
- [ ] 下部UIにCTAが隠れない
- [ ] Page 1だけ見てもHookとして成立
- [ ] Page 8だけ見てもコメント行動が分かる

## 13.6 改行QCは別工程として実施

8ページ全体QCが終わった後、**文字だけを見る2巡目のQC**を行う。

確認方法：

1. 各ページの主見出しを声に出す感覚で読む
2. 改行ごとに一瞬止まっても意味が自然か確認
3. 変な箇所は明示改行で修正
4. 修正したページは再度サムネイル確認

# 14. Step 12｜保存・バージョン管理

Canva名の例：

```text
{テーマ}｜Dark Cinematic｜Layered v1
{テーマ}｜Dark Cinematic｜Layered v2
```

原則として、壊れた版を上書きし続けず、構造を変える大修正では新バージョンを作る。

新規版推奨：

- 背景と文字のレイヤー構造を変更
- ページ数を変更
- デザイン方式を変更
- 既存版の復元が難しい変更

軽微修正として同一版でよい例：

- 改行調整
- 誤字修正
- 数px程度の位置修正

最終版は、8ページサムネイル確認後に保存する。

外部サービス側が保存時の明示承認を要求する場合のみ、必要な最小限の確認をユーザーに求める。

# 15. Step 13｜投稿パックを作る

投稿完成後、必ず次を保存する。

標準保存先：

```text
content/publishing/{ID}_{slug}.md
```

含める内容：

- creative status
- Canva URL
- Caption
- Hashtags
- Pinned comment
- upload order
- cover page
- posting settings
- 投稿前チェック
- 投稿後の対応
- KPI記録欄
- コメント分類
- 派生動画候補

---

# 16. Step 14｜キャプションの作り方

画像ですでに状況を説明しているため、キャプションは長くしすぎない。

標準構成：

```text
Hookの言い換え

A / B
条件変更の問い

思考実験名
コメント要求

#思考実験 #テーマ名 #哲学 #あなたならどうする
```

目的は「もう一度解説すること」ではなく、検索性とコメント参加を補助すること。

---

# 17. Step 15｜固定コメントの作り方

固定コメントは単なる「AかB？」より、投稿からより価値のあるデータを取れる形にする。

推奨：

```text
最初 → 条件変更後で、答えは変わりましたか？

A→A / A→B / B→A / B→B
＋理由を一言
```

テーマによってA/Bでは収まりきらない回答が自然に想定される場合は、補足として「それ以外も理由つきで歓迎」としてよい。

---

# 18. Step 16｜TikTok投稿時の標準設定

- 投稿形式：写真カルーセル
- 順序：Page 1 → 最終ページ
- Cover：Page 1
- Audience：Public
- Comments：ON
- Location：原則なし
- Branded content：該当しない限りOFF
- BGM：文字を読む邪魔をしない低主張のambient / cinematic / suspense系

BGMは投稿時のTikTok内トレンドも考慮して選ぶため、制作工程では固定しなくてよい。

---

# 19. Step 17｜投稿後PDCA

最低限、次のタイミングで記録する。

- 1時間
- 24時間
- 72時間

記録候補：

- views
- likes
- comments
- shares
- saves
- profile views
- follows gained
- average viewing time
- full-view / completion系指標
- search traffic / search terms

### コメントは内容も分類する

二択＋条件変更型なら：

- A→A
- A→B
- B→A
- B→B
- 判定不能

テーマ固有の第三回答が多い場合は追加分類する。

さらに理由をタグ化する。

このデータを次投稿・派生投稿の企画に戻す。

# 21. よくある失敗と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| Canvaで文字が見えない | 全画面背景を後からinsertして前面に来た | 背景プレースホルダーを作り、update_fillで差し替える |
| テキスト要素はあるのに見えない | レイヤー順 | サムネイルで実表示を確認する |
| 画像名は合っているのに内容が違う | アップロード時の命名/対応ミス | ファイル名＋サムネイルの両方で照合 |
| 背景がごちゃつく | 全ページに同じ情報量 | P5/P7/P8を意図的に静かにする |
| オブジェクトが二重になる | 背景にある物体をCanvaでも追加 | 原則「背景1枚＋文字」に戻す |
| 投稿が説明動画化する | 名称・哲学解説から始める | Hookを視聴者の選択に戻す |
| コメントがA/Bだけで終わる | 問いが浅い | 条件変更前後の変化＋理由を聞く |
| 文字がTikTok UIに隠れる | 安全域未確認 | 8ページを実サムネイル＋スマホで確認 |
| 8ページを頼んだのに1枚の絵コンテになる | 画像生成をまとめて依頼した | 1ページ＝1画像で個別生成する |
| 背景に文字や番号が入る | ストーリーボードとして解釈された | no text / no numbersを指定し、ページ単位で再生成 |
| 生成失敗後に品質が急落する | 簡易代替物を本番採用した | 品質基準を維持し、再生成を優先する |
| 既存テンプレートがあるのに別デザインができる | HTML新規生成を優先した | 検証済みテンプレートがあれば最優先で再利用 |
| テキスト置換後に文章が壊れる | 部分置換を場当たり的に実施 | 最終全文と置換順序を先に設計する |
| 文字が変な位置で改行される | 旧テンプレートの自動折り返し | 意味単位で明示改行し、改行QCを別途行う |
| 歴史的説明が不正確になる | 基本形と後世の変形を混同 | Fact Packで由来を分け、Revealで最低限区別する |

# 22. 検証済み再利用ルール

#001・#002の制作を通じ、次を標準とする。

1. **写真カルーセルを第一フォーマット**とする。
2. 標準は**8ページ**。
3. デザインは**Dark Cinematic + Minimal Editorial**。
4. 背景画像は各ページ専用に生成する。
5. **画像生成は1ページ＝1画像を基本にする。**
6. 文字は画像生成時に焼き込まない。
7. Canvaでは背景画像以外の不要なオブジェクトを足さない。
8. Canva背景は**insertではなくupdate_fill**で差し替える。
9. **検証済みCanvaテンプレートがある場合は、新規HTML生成よりテンプレート再利用を優先する。**
10. テキスト差し替え前に、最終全文・強調語・改行位置を確定する。
11. 「テキスト要素がある」ではなく、**8枚の実サムネイルを見てQC**する。
12. **通常QCの後に改行QCをもう1巡行う。**
13. Page 5で最初の選択を取る。
14. Page 6で条件を変える。
15. Page 7で思考実験名を明かす。
16. 基本形と後世の追加条件は混同しない。
17. Page 8で「最初と最後で変わったか」を回収する。
18. 投稿時に固定コメントで変化理由を集める。
19. 投稿後の回答データを次回企画の資産にする。

# 23. 制作開始時の自己チェック

次回投稿を始める前に、ChatGPTは内部的に次を確認する。

```text
[ ] マニュアルを確認した
[ ] Fact Packから開始している
[ ] 投稿文章を先走っていない
[ ] 画像を8ページまとめて生成しようとしていない
[ ] 既存Canvaテンプレートを再利用できるか確認した
[ ] マニュアルにない代替工程を独断で追加していない
```

ユーザーから次の一言があれば、本マニュアルを起点に制作を始める。

```text
次の投稿を作成してください。投稿作成マニュアルに沿って完成まで進めてください。
```

ChatGPTは原則として途中の細かい確認を減らし、判断可能な部分は自律的に進める。

# 25. #002 テセウスの船で得た追加知見

今回の制作では、次の失敗と修正が発生した。
