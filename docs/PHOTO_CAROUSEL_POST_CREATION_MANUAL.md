# 1分思考実験｜TikTok写真カルーセル投稿 作成マニュアル

Version: 1.0  
Established: 2026-08-24  
First validated post: #001 トロッコ問題

---

## 0. このマニュアルの目的

この文書は、「1分思考実験」のTikTok写真カルーセル投稿を、毎回ゼロから考え直さず、一定品質で再現するための標準作業手順（SOP）である。

現在の基本フォーマットは、**9:16の写真カルーセル（スワイプ式）**。顔出し・本人ナレーションに依存せず、視聴者自身を思考実験の主人公にして、画像・短い文章・選択・コメントによって参加させる。

最重要原則は次の5つ。

1. **哲学を説明する前に、視聴者に選ばせる。**
2. 思考実験名から始めず、**「あなたならどうする？」の状況から入る。**
3. 1投稿の中で、**状況 → 選択 → 条件変更 → 再選択**をつくる。
4. 結論を教えて終わらず、**コメント欄を第二部にする。**
5. 背景画像は意味を持たせ、Canvaでは原則として**背景1枚＋編集可能な文字だけ**にする。

---

# 1. 投稿1本の完成条件（Definition of Done）

1本の投稿は、次の状態になった時点で「完成」とする。

- 思考実験のFact Packがある
- 基本状況と論点が事実確認済み
- Hookが視聴者起点になっている
- 7〜9枚程度のカルーセル構成が完成している（標準は8枚）
- 各ページの役割が1つに絞られている
- ページごとの背景画像が生成・確定している
- 背景画像のファイル名とページ対応が記録されている
- Canva上で背景と文字が正しいレイヤー順になっている
- 文字が全ページで実際に表示されている
- 背景の重要オブジェクトを文字が隠していない
- TikTokのUI安全域を侵していない
- A/Bなどの選択肢が中立に表示されている
- 最後に第二の問いまたはコメント誘導がある
- キャプション、ハッシュタグ、固定コメントが完成している
- 投稿後にKPIを記録できる投稿パックが作られている

# 3. Step 1｜テーマを選ぶ

テーマ選定では、「有名か」だけでなく、短尺で視聴者が自分の問題として選択できるかを優先する。

評価軸の例：

- 1〜2枚で状況を理解できるか
- A/Bまたは明確な葛藤があるか
- 条件変更を加えられるか
- コメントで理由が割れそうか
- 背景を視覚化しやすいか
- 思考実験名を知らなくても成立するか

初期シリーズでは、参加しやすさを優先する。

例：

- #001 トロッコ問題
- #002 テセウスの船
- #003 水槽の脳

---

# 4. Step 2｜Fact Packを作る

投稿文章を先に書かない。最初に、思考実験の「変えてはいけない事実」をFact Packとして固定する。

標準保存先：

```text
content/experiments/{ID}_{slug}.yaml
```

Fact Packに最低限含める項目：

- title
- one_line_summary
- core_question
- viewer_role
- initial_state
- available_action
- action_result
- inaction_result
- constraints
- choices
- variation_question
- philosophical_focus
- facts
- sources
- must_include
- must_not_include

### 重要

書籍はテーマ選定・理解の起点として使えるが、**書籍本文やスクリーンショットをそのまま投稿素材にしない。**

投稿用文章は独自に再表現する。必要に応じて原典や信頼できる資料で、基本形・作者・成立時期を確認する。

また、思考実験の変形を使う場合は、基本形と混同しない。

例：トロッコ問題の「その1人が家族だったら？」は、標準的な基本形そのものではなく、投稿内で追加する**条件変更**として扱う。

---

# 5. Step 3｜Hookを決める

Hookは思考実験名ではなく、視聴者の判断から始める。

### 良い形

- 「5人を助けるために、1人を犠牲にできますか？」
- 「全部の部品を交換した船は、まだ同じ船ですか？」
- 「今見ている世界が全部偽物でも、あなたは気づけますか？」

### 避ける形

- 「今日はトロッコ問題を解説します」
- 「哲学者○○が考えた有名な思考実験です」
- 冒頭から答えや思想名を説明する

### Hookの基準

- 1秒で意味が取れる
- 「自分なら？」が発生する
- 続きをスワイプする理由がある
- 固有名詞を知らなくても理解できる

---

# 6. Step 4｜標準8ページ構成

8ページを基本形とする。ただしテーマによって7〜9枚に調整してよい。

| Page | 役割 | 内容 |
|---|---|---|
| 1 | Hook | 一番強い問い。視聴者を止める |
| 2 | Scene | 状況説明。何が起きているか |
| 3 | You / Mechanism | 視聴者の立場・操作可能なもの |
| 4 | Conflict | 選択の結果を明示 |
| 5 | Choice | A/Bなど最初の回答を要求 |
| 6 | Condition Change | 家族・記憶・条件などを変更 |
| 7 | Reveal / Context | 思考実験名と最低限の背景 |
| 8 | Your Answer | 最初と最後の変化＋コメントCTA |

### 構成原則

- 1ページ1メッセージ
- 説明を一気に詰め込まない
- 選択の前に必要な条件は揃える
- 第三の抜け道を勝手に追加しない
- A/Bのどちらかを正解のように見せない
- 思考実験名は後半に出す

---

# 7. Step 5｜文章を確定する

文章は、**画像を見ながら読むカルーセル**として設計する。

### 文章量

- 主見出し：1〜3行
- 補足：1〜2行
- 1ページ内で長文説明しない
- 同じ情報を背景と文章で二重説明しない

### トーン

- 短い
- 直接的
- 「あなた」を使う
- 過剰に煽らない
- 視聴者の人格を評価しない
- 哲学的立場を正解扱いしない

### 強調

重要語だけ暖色ゴールドで強調する。

例：

- 5人
- 1人
- あなた
- 家族
- トロッコ問題
- A / B

---

# 8. Step 6｜背景画像を設計する

現在の標準ビジュアル：

**Dark Cinematic + Minimal Editorial**

### 基本仕様

- 縦 9:16
- 最終Canvas：1080 × 1920
- 深い黒〜チャコール
- 暖色の金・アンバー光
- 必要に応じて冷たいスチール／青黒
- 映画的な霧、光、粒子
- 写実寄り
- 背景に文字・ロゴ・数字・UIを生成しない
- 過剰な血やショッキング描写は使わない

### 画面設計

文字は主に左側に置くため、画像生成時から**左上〜左中央にnegative space**を確保する。

重要オブジェクトは右・右下・中央下へ寄せる。

例：

- レバー → 右下
- 人物 → 中央〜右
- 列車灯 → 遠景中央
- 線路分岐 → 下半分

### 共通画像生成プロンプトの骨格

```text
9:16 vertical cinematic scene for a philosophical thought experiment.
Dark cinematic + minimal editorial aesthetic.
Deep charcoal and black tones, muted warm amber/gold practical light,
selective cool steel shadows, subtle volumetric fog, fine film grain,
realistic materials, restrained composition.
Leave generous dark negative space in the upper-left / left-center for Japanese typography.
Place the key narrative object in the lower-right or right side.
No text, no letters, no numbers, no signage, no logos, no UI, no watermark.
No gore. Avoid generic stock-photo aesthetics.
```

この後に各ページ固有の状況を追加する。

---

# 9. Step 7｜背景画像の役割をページごとに変える

8枚すべてを同じ強度にしない。

| Page | 背景の役割 |
|---|---|
| 1 | Hero。最も強い |
| 2 | 危機・状況を伝える |
| 3 | 操作対象を明確に見せる |
| 4 | 葛藤の構造を見せる |
| 5 | 判断に集中できるミニマル背景 |
| 6 | 感情的な条件変更を視覚化 |
| 7 | 解説を邪魔しない静かな背景 |
| 8 | 余韻。最も静かでもよい |

### 重要

背景画像自体にレバーや線路などが描かれている場合、**Canvaで同じオブジェクトを追加しない。**

原則：

> 完成した背景画像 ＋ 文字

だけで成立させる。

---

# 10. Step 8｜画像名とページ対応を固定する

画像生成後は、Canvaに入れる前にページ対応を確定する。

標準記録形式：

```text
Page 1: {filename}
Page 2: {filename}
...
Page 8: {filename}
```

ファイル名は生成時の英語名をそのまま利用してもよい。重要なのは、**ページ番号との対応表を正本として残すこと。**

アップロード後は、ファイル名だけでなくサムネイルも照合する。

---

# 11. Step 9｜Canvaへの組み込み

## 11.1 推奨方式

**HTMLテンプレートをCanvaへインポート → 背景プレースホルダーのfillを生成画像へ差し替える。**

これを標準方式とする。

### HTMLの基本条件

- 1080 × 1920
- 8つのトップレベルページ
- 各ページに `data-document-role="page"`
- 必要なら `data-label` を付ける
- 背景用の全画面画像／shapeを最初から1つ入れる
- その後ろ／前面関係を保った状態でテキストを置く

---

## 11.2 最重要：Canvaレイヤー事故を防ぐ

#001制作で実際に起きた失敗：

1. 文字だけのCanvaデザインを作った
2. 後から全画面背景画像を `insert` した
3. Canva上では新しい背景画像が文字より前面に積まれた
4. テキスト要素自体は存在するのに、画面では文字が見えなくなった

### NG

```text
文字を先に作成
↓
完成画像を全画面で後からinsert
```

### 正解

```text
背景プレースホルダーを最初から作る
↓
その上に文字を作る
↓
Canvaにインポート
↓
背景プレースホルダーのupdate_fillで画像だけ交換
```

**背景を新規挿入するのではなく、既存背景fillを差し替える。**

これにより、背景は後ろ、文字は前面のまま維持できる。

# 12. Step 10｜Canvaデザイン仕様

### Canvas

- 1080 × 1920

### 安全域の目安

- Left: 72〜76px以上
- Top: 150〜200px以降を主領域にする
- Right: TikTok UIを考え、重要文字は右端まで伸ばさない
- Bottom: 320〜380px程度をUI回避域として意識

### 標準文字位置

- ブランド名：上部左
- ページ番号：上部右だが、右端から十分内側
- 英語kicker：上部左
- 主見出し：上〜中央
- 補足：下側だがTikTok UIより上

### 文字サイズの目安

- 主見出し：約80〜90px
- 本文：約48〜54px
- 小見出し：約22〜34px
- A/B：約60px前後

### 配色

- 本文：off-white / white
- 強調：warm gold
- 背景：dark charcoal / black

---

# 13. Step 11｜Canva最終QC

「要素が存在する」だけでは合格にしない。

**実際のサムネイルを8ページすべて見る。**

チェック項目：

### 表示

- [ ] 文字が実際に見えている
- [ ] 背景が文字を覆っていない
- [ ] 画像が欠けていない
- [ ] ページ番号が1/8〜8/8になっている

### 読みやすさ

- [ ] 主見出しが背景に埋もれていない
- [ ] ゴールド文字のコントラストが十分
- [ ] 文字が重要オブジェクトを隠していない
- [ ] 1ページの文章量が多すぎない

### 意味

- [ ] 背景と文章の意味が一致している
- [ ] Page 3など、必要なオブジェクトが明瞭
- [ ] Page 4など、葛藤構造が視覚的に伝わる
- [ ] A/Bが中立
- [ ] 条件変更が基本形と混同されていない

### TikTok

- [ ] 右側UIに重要文字が重ならない
- [ ] 下部UIにCTAが隠れない
- [ ] Page 1だけ見てもHookとして成立
- [ ] Page 8だけ見てもコメント行動が分かる

# 14. Step 12｜保存・バージョン管理

Canva名の例：

```text
{テーマ}｜Dark Cinematic｜Layered v1
{テーマ}｜Dark Cinematic｜Layered v2
```

原則として、壊れた版を上書きし続けず、構造を変える大修正では新バージョンを作る。

特に次の場合は新規版推奨：

- 背景と文字のレイヤー構造を変更
- ページ数を変更
- デザイン方式を変更
- 既存版の復元が難しい変更

最終版は、8ページサムネイル確認後に保存する。

# 15. Step 13｜投稿パックを作る

投稿完成後、必ず次を保存する。

標準保存先：

```text
content/publishing/{ID}_{slug}.md
```

含める内容：

- creative status
- Canva URL
- Caption
- Hashtags
- Pinned comment
- upload order
- cover page
- posting settings
- 投稿前チェック
- 投稿後の対応
- KPI記録欄
- コメント分類
- 派生動画候補

---

# 16. Step 14｜キャプションの作り方

画像だけですでに状況を説明しているため、キャプションは長くしすぎない。

標準構成：

```text
Hookの言い換え

A / B
条件変更の問い

思考実験名
コメント要求

#思考実験 #テーマ名 #哲学 #あなたならどうする
```

目的は「もう一度解説すること」ではなく、検索性とコメント参加を補助すること。

---

# 17. Step 15｜固定コメントの作り方

固定コメントは単なる「AかB？」より、投稿からより価値のあるデータを取れる形にする。

推奨：

```text
最初 → 条件変更後で、答えは変わりましたか？

A→A / A→B / B→A / B→B
＋理由を一言
```

これにより、単純回答だけでなく「条件によって判断が変わるか」が取れる。

---

# 18. Step 16｜TikTok投稿時の標準設定

- 投稿形式：写真カルーセル
- 順序：Page 1 → 最終ページ
- Cover：Page 1
- Audience：Public
- Comments：ON
- Location：原則なし
- Branded content：該当しない限りOFF
- BGM：文字を読む邪魔をしない低主張のambient / cinematic / suspense系

BGMは投稿時のTikTok内トレンドも考慮して選ぶため、制作工程では固定しなくてよい。

---

# 19. Step 17｜投稿後PDCA

最低限、次のタイミングで記録する。

- 1時間
- 24時間
- 72時間

記録候補：

- views
- likes
- comments
- shares
- saves
- profile views
- follows gained
- average viewing time
- full-view / completion系指標
- search traffic / search terms

### コメントは内容も分類する

二択＋条件変更型なら：

- A→A
- A→B
- B→A
- B→B
- 判定不能

さらに理由をタグ化する。

例：

- 人数重視
- 行為 / 不作為
- 家族優先
- 責任回避
- 感情
- 公平性
- その他

このデータを次投稿・派生投稿の企画に戻す。

# 21. よくある失敗と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| Canvaで文字が見えない | 全画面背景を後からinsertして前面に来た | 背景プレースホルダーを作り、update_fillで差し替える |
| テキスト要素はあるのに見えない | レイヤー順 | サムネイルで実表示を確認する |
| 画像名は合っているのに内容が違う | アップロード時の命名/対応ミス | ファイル名＋サムネイルの両方で照合 |
| 背景がごちゃつく | 全ページに同じ情報量 | P5/P7/P8を意図的に静かにする |
| レバーなどが二重になる | 背景にある物体をCanvaでも追加 | 原則「背景1枚＋文字」に戻す |
| 投稿が説明動画化する | 名称・哲学解説から始める | Hookを視聴者の選択に戻す |
| コメントがA/Bだけで終わる | 問いが浅い | 条件変更前後の変化＋理由を聞く |
| 文字がTikTok UIに隠れる | 安全域未確認 | 8ページを実サムネイル＋スマホで確認 |

# 22. #001 トロッコ問題で確立した再利用ルール

今回の制作で、次を標準として採用する。

1. **写真カルーセルを第一フォーマット**とする。
2. 標準は**8ページ**。
3. デザインは**Dark Cinematic + Minimal Editorial**。
4. 背景画像は各ページ専用に生成する。
5. 文字は画像生成時に焼き込まない。
6. Canvaでは背景画像以外の不要なオブジェクトを足さない。
7. Canva背景は**insertではなくupdate_fill**で差し替える。
8. 「テキスト要素がある」ではなく、**8枚の実サムネイルを見てQC**する。
9. Page 5で最初の選択を取る。
10. Page 6で条件を変える。
11. Page 7で思考実験名を明かす。
12. Page 8で「最初と最後で変わったか」を回収する。
13. 投稿時に固定コメントで変化理由を集める。
14. 投稿後の回答データを次回企画の資産にする。

# 23. 次回投稿を始めるときの最短指示

ユーザーから次の一言があれば、本マニュアルを起点に制作を始める。

```text
次の投稿を作成してください。投稿作成マニュアルに沿って完成まで進めてください。
```

ChatGPTは原則として途中の細かい確認を減らし、判断可能な部分は自律的に進める。

ただし、外部サービス側の仕様で保存・公開などに明示承認が必要な場合は、その操作に必要な最小限の確認だけを求める。

  ↓

  ↓

## 付記：現行リポジトリの動画パイプラインとの関係

リポジトリには従来の縦型動画生成パイプラインも残っている。

これは将来的な動画展開・比較検証用として保持するが、**現時点のTikTok初期運用では、本マニュアルの写真カルーセル制作フローを優先する。**

動画資産やFact Packは再利用可能なので、将来カルーセルで反応が良かったテーマを動画化する運用も可能。
