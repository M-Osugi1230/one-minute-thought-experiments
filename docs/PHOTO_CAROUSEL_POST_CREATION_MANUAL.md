# 1分思考実験｜TikTok写真カルーセル投稿 作成マニュアル

Version: 1.4  
Updated: 2026-08-26  
Validated posts: #001 トロッコ問題 / #002 テセウスの船 / #003 水槽の中の脳

---

## 0. このマニュアルの目的

この文書は、「1分思考実験」のTikTok写真カルーセル投稿を、毎回ゼロから考え直さず、別チャット・別テーマでも同じ思想・工程・品質で再現するための標準作業手順（SOP）兼成果物仕様書である。

現在の第一フォーマットは、**9:16の写真カルーセル（スワイプ式）**。顔出し・本人ナレーションに依存せず、視聴者自身を思考実験の主人公にして、画像・短い文章・選択・コメントによって参加させる。

本マニュアルでは、ブレ防止のために以下を明確に分ける。

- **固定するもの**：制作順序、Fact Pack、Hook選定手順、Brand Shell、品質基準、投稿パック、保存確認
- **柔軟にするもの**：テーマ、ページ数、Reveal位置、Episode Skin、背景構図、本文Text Zone

最重要原則は次の12点。

1. **哲学を説明する前に、視聴者に考えさせる。**
2. 思考実験名から始めず、**「あなたならどうする？」の状況から入る。**
3. 原則として、**状況 → 葛藤 → 選択 → 条件変更 → 再考**をつくる。
4. 結論を教えて終わらず、**コメント欄を第二部にする。**
5. 背景画像は意味を持たせ、Canvaでは原則として**背景1枚＋編集可能な文字だけ**にする。
6. **Brand Shellは固定し、Episode Skinはテーマに合わせて変える。**
7. **Cinematic + realistic + minimal editorial**をシリーズの親画風とする。
8. トレンドは作品の主役にせず、**テーマ選定・Hook・投稿タイミングの追い風として利用する。**
9. テーマは本の順番で固定せず、**制作開始直前に候補群から最適なものを選ぶ。**
10. Hookは毎回複数案を内部比較し、**通常は採用案のみを成果物として出す。**
11. 制作開始後は、重大な分岐がない限り**途中確認を求めず完成まで進める。**
12. テンプレート再利用時は、旧作品の色・強調・改行・配置・文言残存を全ページ監査する。

# 1. 投稿1本の完成条件（Definition of Done）

以下をすべて満たした時点で「完成」とする。

- テーマ選定理由が記録されている
- 思考実験のFact Packがある
- 基本状況と論点が事実確認済み
- 基本形と後世の変形・追加条件が区別されている
- Hookを最低5案内部生成・比較し、採用Hookが確定している
- ページ数とその理由が確定している
- 各ページの役割が1つに絞られている
- 各ページの文章が確定している
- **意図した改行位置と強調語まで文章仕様として確定している**
- 思考実験名は原則として後半まで明かしていない
- ページごとの背景画像が生成・確定している
- 背景画像のファイル名とページ対応が記録されている
- ページごとのText Zoneが決まっている
- Canva上で背景と文字が正しいレイヤー順になっている
- 文字が全ページで実際に表示されている
- **不自然な自動折り返しが残っていない**
- 背景の重要オブジェクトを文字が隠していない
- TikTokのUI安全域を侵していない
- A/B等の選択肢が中立に表示されている
- 最終ページに第二の問いまたはコメント誘導がある
- **全ページに「1分思考実験」のブランド名がある**
- **全ページにページ番号がある**
- **Page 1に明確なスワイプ誘導がある**
- 英語kickerがシリーズ共通の仕組みとして配置されている
- Brand Shellの基本位置・余白・情報階層が一貫している
- Episode Skinがテーマに合っている
- **複製元テンプレートの旧アクセント色が意図せず残っていない**
- **主要テキストが背景に対して十分なコントラストを持つ**
- 最終ページが縮小表示でも主質問・選択肢・コメント誘導を一目で把握できる
- 全ページの実サムネイルを確認済み
- **TikTokタイトルが確定している**
- キャプション、ハッシュタグ、固定コメント、BGM方向性が完成している
- 投稿後にKPIを記録できるProduction Packが作られている

# 2. 成果物の順序｜絶対に崩さないOutput Contract

各投稿では、原則として次の順番で成果物を確定する。

```text
Theme / Why Now
  ↓
Fact Pack
  ↓
Hook Selection
  ↓
Page Plan
  ↓
Final Copy
  ↓
Line Breaks / Emphasis
  ↓
Brand Shell Check
  ↓
Episode Skin / Art Direction
  ↓
Image Plan
  ↓
Page-by-page Image Generation
  ↓
Image Mapping
  ↓
Text Zone
  ↓
Canva Implementation
  ↓
QC
  ↓
TikTok Title
  ↓
Caption
  ↓
Hashtags
  ↓
Pinned Comment
  ↓
BGM Direction
  ↓
Production Pack Save
```

**今回は画像から先に作る、今回はCanvaから触る、今回はHookを後で決める、という順序変更は原則しない。**

例外は、ユーザーから明示的な指定がある場合、または既存素材を再利用する場合のみ。

# 3. Step 1｜テーマを選ぶ

## 3.1 投稿順は固定しない

101個を本の順番や事前ランキング通りに機械的に投稿しない。

制作開始直前に、候補群からその時点で最適なテーマを選ぶ。

原則フロー：

```text
候補プールを作る
↓
コンテンツ力を評価
↓
社会との接続度・タイミングを評価
↓
上位候補を比較
↓
採用テーマを1件決定
```

## 3.2 評価は「コンテンツ力80 + タイミング20」

テーマ選定は100点満点で評価する。

### コンテンツ力：80点

- Hook力
- 自分事化しやすさ
- 意見分裂性
- 短尺で理解できるか
- 条件変更・再考を作れるか
- 映像化しやすさ
- Evergreen性

### タイミング / 社会との接続度：20点

- 今、人々が考えやすいテーマか
- AI、格差、SNS、仕事、孤独、科学、未来などの社会的関心と自然につながるか
- 一過性ニュースに依存しすぎず、今出す理由があるか

**タイミング20点だけで、本来弱いテーマを採用しない。**

## 3.3 トレンドの扱い

トレンドは主役にしない。

原則：

- 思考実験そのものはEvergreenにする
- トレンドはテーマ選定、Hook、投稿タイミングに利用する
- 特定ニュース名・企業名・サービス名は必要性がある場合のみ使う
- 「ChatGPTが〜」より「AIが〜」のように、動画寿命が長くなる抽象度を優先する
- ニュース解説投稿へ変質させない

考え方：

> 「何が流行っているか？」ではなく、
> **「なぜ今、この普遍的な問いを出すと刺さるのか？」**

# 4. Step 2｜Fact Packを作る

投稿文章より先に、思考実験の「変えてはいけない事実」を固定する。

標準保存先：

```text
content/experiments/{ID}_{slug}.yaml
```

最低限含める項目：

- title
- one_line_summary
- core_question
- viewer_role
- initial_state
- available_action
- action_result
- inaction_result
- constraints
- choices
- variation_question
- philosophical_focus
- facts
- sources
- must_include
- must_not_include

### 原典と変形

- 書籍はテーマ選定・理解の起点として使える
- 書籍本文やKindle画面をそのまま投稿素材にしない
- 必要に応じて原典や信頼できる資料で、基本形・作者・成立時期を確認する
- 後世のバリエーションや独自条件は、基本形と混同しない

短尺化のために説明を削っても、歴史的・概念的な区別は壊さない。

# 5. Step 3｜Hookを決める

## 5.1 Hook生成手順

毎回、最低5案を内部で作る。

通常は5案すべてをユーザーへ提示しない。

```text
5案以上生成
↓
1秒理解性
↓
自分事化
↓
葛藤・謎
↓
スワイプ理由
↓
過剰煽りがないか
↓
最上位1案を採用
```

必要な場合のみ候補案を開示する。

## 5.2 Hookの基本形

原則として、

```text
あなた + 事件 / 条件 + 問い
```

で設計する。

良い例：

- 「5人を助けるために、1人を犠牲にできますか？」
- 「全部の部品を交換した船は、まだ同じ船ですか？」
- 「今見ている世界が全部偽物でも、あなたは気づけますか？」

避ける例：

- 「今日は○○を解説します」
- 「○○という思考実験があります」
- 冒頭から哲学者名や結論を説明する

### 合格条件

- 1秒で意味が取れる
- 「自分なら？」が発生する
- 続きをスワイプする理由がある
- 固有名詞を知らなくても成立する
- 過剰に誇張・煽動していない

## 5.3 Page 1のスワイプ誘導

標準文言：

```text
スワイプして考える　›
```

文言はABテストしてよいが、**スワイプ誘導自体はBrand Shell固定要件**。

# 6. Step 4｜ページ構成を決める

## 6.1 標準は8ページ。ただし固定しない

最初は8ページで設計する。

標準形：

| Page | 役割 | 内容 |
|---|---|---|
| 1 | Hook | 一番強い問い |
| 2 | Scene | 状況説明 |
| 3 | You / Mechanism / Change | 視聴者の立場・仕組み・変化 |
| 4 | Conflict | 葛藤・矛盾 |
| 5 | Choice | 最初の回答 |
| 6 | Condition Change | 条件変更 |
| 7 | Reveal / Context | 思考実験名・最低限の背景 |
| 8 | Your Answer | 再考・回答・CTA |

ただし、これは**参考骨格であり固定テンプレートではない。**

## 6.2 7枚に減らす条件

- 説明のためだけの薄いページが1枚生まれる
- 2ページを自然に統合した方がテンポが良い
- 8枚にすることで同じ内容を重複する

## 6.3 9枚に増やす条件

- 条件変更や二段階選択を1ページへ詰めると理解度が落ちる
- 重要な葛藤を飛ばさないと8枚に収まらない
- Reveal前後に必要な余白が不足する

**枚数合わせのために内容を水増し・圧縮しない。**

## 6.4 Reveal位置

固定ページにはしない。

ルールは1つだけ：

> **思考実験名・哲学的背景は原則として後半まで明かさない。**

Page 7が標準だが、テーマによってPage 6・8等へ動かしてよい。

## 6.5 構成原則

- 1ページ1メッセージ
- 説明を詰め込まない
- 選択前に必要条件を揃える
- 第三の抜け道を勝手に追加しない
- A/Bのどちらかを正解のように見せない
- 最後に再考・第二の問い・理由コメントのいずれかを残す

---

# 7. Step 5｜文章を確定する

### 文章量

現行基準を維持する。

- 主見出し：1〜3行を目安。意味上必要なら4行可
- 補足：1〜2行を基本
- 1ページ内で長文説明しない
- 同じ情報を背景と文章で二重説明しない

文字数上限は機械的に設けない。

### トーン

- 短い
- 直接的
- 「あなた」を使う
- 過剰に煽らない
- 視聴者の人格を評価しない
- 哲学的立場を正解扱いしない

### 強調

重要語のみEpisode Accentで強調する。

- アクセント色は作品ごとに可変
- 1ページ内で乱用しない
- A/Bは中立性を最優先し、同色・同サイズ・同ウェイトを基本とする

## 7.1 改行は文章仕様

文章確定時に改行位置も決める。

良い例：

```text
全部の部品を
交換した船は、
まだ同じ船ですか？
```

### 改行ルール

- 意味のかたまりで切る
- 助詞だけを孤立させない
- 主語と述語を極端に離さない
- 強調語が自然に見える行構成にする
- 1行を極端に短くしない
- 文字サイズを先に小さくして逃げない
- A/Bは可能な限り1選択肢＝1行

# 8. Step 6｜Brand ShellとEpisode Skin

## 8.1 Brand Shell｜原則固定

- 1080 × 1920 / 9:16
- 全ページの「1分思考実験」
- 全ページのページ番号
- ブランド名・ページ番号の基本位置
- 英語kickerという情報階層
- 主見出し・補足・A/Bの基本的なサイズ階層
- TikTok UI安全域
- Page 1のスワイプ誘導
- 背景1枚＋編集可能文字を基本とするCanva構造
- 中盤で判断を要求する設計
- 最終ページのコメントCTA

**Brand Shellはテーマが変わっても外さない。**

## 8.2 Episode Skin｜テーマごとに可変

変更可：

- 背景色
- アクセント色
- 光源色
- 霧・粒子・グリッチ等の質感
- 時代感
- 背景モチーフ
- kickerの具体語

例：

```text
#001 トロッコ問題
dark charcoal + warm amber
現実的 / 重厚 / 倫理的緊張

#002 テセウスの船
dark charcoal + wood + aged amber
古典 / 歴史 / 静かな違和感

#003 水槽の中の脳
black / navy + cyan + restrained glitch
SF / simulation mystery / 現実崩壊感
```

## 8.3 親画風は固定

シリーズ全体の親スタイル：

```text
Cinematic
Realistic
Minimal Editorial
Restrained Lighting
Controlled Information Density
```

明確な理由がない限り、アニメ調・ポップイラスト調・過度な3Dキャラクター調等へ逸脱しない。

テーマに合わせた変化は、親画風の内部で行う。

## 8.4 テンプレート色移行

Episode Skin変更は「数か所の色変更」ではなく、**旧色→新色の移行工程**として扱う。

編集前に定義する：

```text
Base text
Episode accent
Secondary accent if any
Legacy accent from source template → 原則0件
A/B style
```

編集後は全ページを横断して旧色残存を確認する。

# 9. Step 7｜背景画像を設計する

### 共通仕様

- 9:16 vertical
- 最終Canvas 1080 × 1920
- Cinematic + realistic + minimal editorial
- 情報量を制御
- 写実寄り
- negative spaceを確保
- 背景に文字・ロゴ・数字・UIを生成しない
- 過剰な血・ショッキング描写は使わない
- generic stock photo感を避ける

標準では左上〜左中央にnegative spaceを確保し、主要オブジェクトを右・右下・中央下へ寄せる。

ただし最終文字位置は固定しない。

**「左に置くこと」より「一瞬で読めること」を優先する。**

### 共通プロンプト骨格

```text
9:16 vertical cinematic scene for a philosophical thought experiment.
Cinematic + minimal editorial aesthetic.
Realistic materials, restrained composition, subtle atmosphere and filmic texture.
Use an episode-specific palette and lighting.
Leave generous negative space for Japanese typography.
Keep the key narrative object away from the primary text zone.
No text, no letters, no numbers, no signage, no logos, no UI, no watermark.
No gore. Avoid generic stock-photo aesthetics.
```

## 9.1 1ページ＝1画像

複数ページを1回でまとめて生成しない。

```text
Page 1 → 1画像
Page 2 → 1画像
...
最終Page → 1画像
```

特にHook、Choice、Condition Change、Reveal、Final Answerは厳しく見る。

## 9.2 生成失敗時

1. ページ単位でプロンプト修正
2. 再生成
3. それでも難しい場合のみ別方式を検討
4. 品質が下がる代替物は本番採用しない

勝手に簡易Python背景等へ迂回しない。

## 9.3 Text Zone

背景確定後、各ページについて必ず決める。

```text
Primary text zone: left / center / right
Secondary text zone: left / center / right
Bright areas to avoid: ...
Key objects to protect: ...
```

Brand Shell固定と本文位置固定を混同しない。

---

# 10. Step 8｜背景の強度を変える

全ページを同じ情報量にしない。

標準：

- Hook：Hero。最も強い
- Scene：状況理解
- Mechanism：変化を明確に
- Conflict：葛藤構造
- Choice：判断に集中できるミニマル背景
- Condition Change：変更条件を明確に
- Reveal：文字を邪魔しない
- Final：余韻＋最終質問の可読性を最優先

背景画像に重要オブジェクトがある場合、Canvaで同じオブジェクトを重ねない。

原則：

> **完成背景 + Brand Shell + 投稿本文**

だけで成立させる。

---

# 11. Step 9｜画像名とページ対応

生成後、Canva投入前に対応表を正本として固定する。

```text
Page 1: {filename}
Page 2: {filename}
...
Page N: {filename}
```

ファイル名だけでなくサムネイルでも照合する。

# 12. Step 10｜Canva組み込み

## 12.1 テンプレート再利用を優先

検証済みテンプレートがある場合：

```text
既存テンプレート複製
↓
Brand Shell維持
↓
背景fill差し替え
↓
本文差し替え
↓
Episode Skin色移行
↓
Text Zone調整
↓
QC
```

新規方式は、再利用テンプレートが適さない場合に限る。

## 12.2 レイヤー事故防止

全画面背景画像を後からinsertしない。

正解：

```text
背景プレースホルダー
↓
その上にBrand Shellと本文
↓
背景fillをupdate_fillで差し替える
```

## 12.3 テキスト差し替え

- 先に最終全文を確定
- 強調語・改行も確定
- 場当たり的な部分置換をしない
- 置換直後に文法を確認
- 旧テーマ固有語を確認
- Brand Shellを消さない

## 12.4 A/B

不自然な折り返しがある場合：

```text
1. テキストボックス幅
2. 位置
3. 行間
4. 最後にフォントサイズ
```

A/Bは原則として：

- 同サイズ
- 同色
- 同ウェイト
- 同幅
- 同整列基準

# 13. Step 11｜Canvaデザイン仕様

### Canvas

- 1080 × 1920

### 安全域目安

- Left: 72〜76px以上
- Top: 150〜200px以降を主領域
- Right: TikTok UIを考慮
- Bottom: 320〜380px程度をUI回避域として意識

### Brand Shell標準位置

- ブランド名：上部左
- ページ番号：上部右
- kicker：ブランド名の下
- 主見出し：上〜中央
- 補足：下側だがUIより上
- Page 1スワイプ誘導：主見出しより下位階層

本文・A/B・CTAは背景Text Zoneに合わせて左右移動してよい。

### 文字サイズ目安

- 主見出し：約72〜90px
- 本文：約48〜54px
- kicker：約22〜34px
- A/B：約52〜60px

### 配色

固定：

- 本文：off-white / whiteを基本
- ブランド名・ページ番号：高コントラストneutral light

可変：

- Episode accent
- 背景色
- kicker色

warm goldはブランド必須色ではない。

### コントラスト改善の優先順位

```text
1. 暗いText Zoneへ移動
2. 幅・改行調整
3. 重要オブジェクト干渉確認
4. 文字色調整
5. 必要なら背景再選定・再生成
```

# 14. Step 12｜最終QC

「要素が存在する」だけでは合格にしない。**全ページの実サムネイルを見る。**

## 14.1 Brand Shell

- [ ] 全ページに「1分思考実験」
- [ ] 全ページにページ番号
- [ ] ブランド位置が揃っている
- [ ] kickerがある
- [ ] kickerがページ役割と一致
- [ ] Page 1にスワイプ誘導

## 14.2 表示

- [ ] 文字が実際に見える
- [ ] 背景が文字を覆っていない
- [ ] 画像欠けなし
- [ ] 背景に不要な文字・数字・ロゴ・UIなし
- [ ] Canva文字と背景内文字の二重化なし

## 14.3 読みやすさ

- [ ] 主見出しが背景に埋もれていない
- [ ] 発光部へ文字列の一部だけ跨いでいない
- [ ] アクセント色のコントラスト十分
- [ ] 重要オブジェクトを隠していない
- [ ] 文章量が多すぎない
- [ ] 不自然な改行なし
- [ ] 短すぎる孤立行なし
- [ ] A/B片側だけ折り返していない

## 14.4 文章・意味

- [ ] 文法が成立
- [ ] 旧テーマ語なし
- [ ] 内容重複なし
- [ ] 背景と文章の意味一致
- [ ] 葛藤が伝わる
- [ ] A/B中立
- [ ] 条件変更が基本形と混同されていない
- [ ] Revealが短くても正確

## 14.5 TikTok

- [ ] 右側UIに重要文字が重ならない
- [ ] 下部UIにCTAが隠れない
- [ ] Page 1単体でHook成立
- [ ] Page 1単体でスワイプ投稿と分かる
- [ ] 最終Page単体で主質問→選択→コメント誘導の視線が流れる

## 14.6 Episode Skin

- [ ] テーマに色・光・質感が合う
- [ ] 前作と違ってもブランド認識可能
- [ ] 前作と同系統なら不必要に画風を変えていない
- [ ] 親画風を逸脱していない
- [ ] 演出が可読性を損なっていない

## 14.7 旧色QC

通常QCとは別に、色だけを見る1巡を行う。

- 許可色を確認
- 全ページ確認
- 複製元旧アクセント色を探す
- 意図しない旧色は0件にする

## 14.8 改行QC

通常QC後、文字だけを見る1巡を行う。

- 改行ごとに意味が自然か
- A/B折り返し
- 強調語位置
- 修正後サムネイル再確認

## 14.9 スマホ縮小QC / 1秒判定

特にHook、Choice、Finalを厳しく見る。

最終ページは約1秒で最低限、

```text
1. 最終質問
2. 選択肢
3. 理由をコメントすること
```

が順番に認識できること。

# 15. Step 13｜保存・バージョン管理

構造変更では新バージョン、軽微修正は同一版でよい。

- ページ数変更
- デザイン方式変更

### 軽微修正

- 改行
- 誤字
- 本文位置
- Episode Skin内の軽微な色
- Text Zone調整

### 編集セッション失効時

```text

4. 対象ページQC
5. commit
6. commit成功確認
```

# 18. Step 16｜キャプション

目的は再説明ではなく、検索性とコメント参加の補助。

# 19. Step 17｜固定コメント

標準：

```text

```

テーマに応じて自由回答形式へ変えてよい。

# 24. 途中確認ルール

制作開始後は、原則として途中確認を求めず完成まで進める。

## 確認が必要な例外

- 原典について重大な解釈分岐がある
- ユーザーしか持っていない素材が必要
- 既存ブランド方針を大きく変更する必要がある
- 外部サービス上の不可逆操作で明示承認が必要

## 確認不要

- ページ数7/8/9判断
- Episode Skin選定
- 画像生成の再試行

- 改行調整

# 25. よくある失敗と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| Canvaで文字が見えない | 背景を後からinsert | 背景fillをupdate_fill |
| テキスト要素はあるが見えない | レイヤー順 | 実サムネイル確認 |
| 画像名と内容が違う | 対応ミス | ファイル名＋サムネイル照合 |
| 背景がごちゃつく | 全ページ同強度 | Choice / Reveal / Finalを静かに |
| オブジェクトが二重 | 背景とCanvaで重複 | 背景＋文字へ戻す |
| 背景に文字が焼き込まれる | 生成指示不足 | no text / no numbers |
| 投稿が説明コンテンツ化 | 名前から始めた | Hookを視聴者起点へ |
| コメントが浅い | A/Bだけ | 条件変更＋理由を聞く |
| UIに文字が隠れる | 安全域不足 | 実サムネイル＋スマホQC |
| 8ページが1枚絵になる | まとめて画像生成 | 1ページ＝1画像 |
| 生成失敗後に品質低下 | 簡易代替採用 | 再生成優先 |
| 別デザインができる | 新規方式を優先 | 検証済みテンプレート再利用 |
| 文章が壊れる | 場当たり置換 | 最終全文を先に確定 |
| 不自然な改行 | 自動折り返し | 明示改行＋改行QC |
| A/B片方だけ2行 | 幅不足 | 幅→位置→行間→サイズ |
| 原典説明が不正確 | 基本形と変形混同 | Fact Packで分離 |
| ブランド名が消える | SkinとShell混同 | Brand Shell固定 |
| 全作品同じ色 | 色をブランド要素と誤認 | Episode Skin可変 |
| 旧色が残る | 色移行工程不足 | 旧色QC独立実施 |
| 白文字が溶ける | 本文位置固定 | Text Zone移動を優先 |
| スマホで読みにくい | 大画面QCのみ | 1秒縮小QC |
| 最終Pageが弱い | 視線導線不足 | 質問→選択→理由CTA |
| 保存済みと誤報 | commit未確認 | commit成功後のみ報告 |
| 作品ごとに成果物形式が違う | Output Contract未遵守 | Production Pack順序固定 |
| トレンド依存で古くなる | ニュース名に寄せすぎ | Evergreenへ抽象化 |
| 8枚に無理やり合わせる | 枚数固定 | 7/8/9判断ルールを使う |

# 28. #001〜#003から得た確定知見

## #001 トロッコ問題

- Page 1のスワイプ誘導が有効
- 背景を後からinsertすると文字が隠れる
- 背景fill差し替えが安全

## #002 テセウスの船

- 複数ページまとめ生成はストーリーボード化しやすい
- 簡易代替への迂回は品質低下を招く
- 既存テンプレートがあるなら再利用優先
- 自動折り返しは意味を壊す
- 基本形と後世の追加条件を区別する

## #003 水槽の中の脳

- Brand ShellとEpisode Skin分離は有効
- テンプレート色移行は独立工程が必要
- A/Bはテキスト幅を先に見る
- 白背景×白文字では本文Text Zoneを動かす
- スマホ縮小QCが必要
- commit前の編集セッション失効に備える

### 共通結論

- 色・光・質感まで完全一致させない
- Brand Shellでシリーズ認識を担保する
- Episode Skinで作品固有の世界を作る
- 文字位置より可読性優先
- 説明より参加
- 回答データを次投稿へ戻す
